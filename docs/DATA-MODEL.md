# Atlas OS — Data Model (Phase 1)

All tables live in one Postgres schema. Every owner-controlled table carries
`user_id` and is queried with it. IDs are UUIDv7 (time-ordered) generated in
the application. Timestamps are `timestamptz`. Soft deletion uses
`archived_at` or `status`; nothing user-visible is hard-deleted.

```
user ─┬─< session / account / verification / passkey        (Better Auth)
      ├── user_profile                                       (core memory block)
      ├─< venture ─< project
      ├─< conversation ─< message ─< tool_invocation
      ├─< memory  (provenance → message, optional project)
      └─< atlas_event                                        (audit / event spine)
```

## Auth (owned by Better Auth, generated via `npx auth generate`)

`user`, `session`, `account`, `verification`, `passkey`. We extend `user`
with `role` (`owner`) and keep registration closed via allowlist. Do not add
domain columns to `user`; use `user_profile`.

## Sensitive fields

Nothing in Phase 1 is classified `sensitive` yet. When health, financial, or
similar data arrives, columns are stored as `bytea` ciphertext via
`src/core/crypto` with a sibling `*_bidx` HMAC column when exact lookup is
needed. The helper and its tests ship in Phase 1 so the pattern exists
before the data does.

## Reserved for Phase 2+

`artifact` (documents/files), `memory_entity` / `memory_edge` (graph),
`integration` + `integration_grant`, `operative` + `operative_run`,
`brief`, `notification`, `health_*`, `workspace`.
